### План добавления функции "Создать PDF из папки"

**1. Цель**

Добавить возможность массового объединения PDF-приложений из выбранной папки с основным отчетом. Это позволит обрабатывать более 6 приложений за раз. Существующий функционал для 6 слотов должен остаться без изменений.

**1.1. Принцип разделения функций**

Вводятся две независимые кнопки для двух разных сценариев:

*   **"📚 Создать общий PDF" (Существующая кнопка):**
    *   **Использует:** Основной отчет + Файлы из 6 ручных слотов.
    *   **Игнорирует:** Функционал выбора папки.

*   **"🗂️ Создать PDF из папки" (Новая кнопка):**
    *   **Использует:** Основной отчет + ВСЕ PDF-файлы из выбранной папки.
    *   **Игнорирует:** Файлы, добавленные в 6 ручных слотов.

Эти две операции не пересекаются, что обеспечивает предсказуемость работы каждой кнопки.

**2. Изменения в пользовательском интерфейсе (`pdf_attachments_ui.py`)**

*   В `bottom_btn_frame`, рядом с существующими кнопками "Сброс" и "Создать общий PDF", будет добавлена новая кнопка:
    *   **Текст:** `🗂️ Создать PDF из папки`
    *   **Действие:** Кнопка будет вызывать новую функцию `create_merged_pdf_from_folder()`.

**3. Новая функция `create_merged_pdf_from_folder()` в `pdf_attachments_ui.py`**

Эта функция будет ядром новой функциональности.

*   **Шаг 1: Подготовка основного отчета.**
    *   Логика определения и подготовки основного отчета (из Word или PDF) будет полностью заимствована из существующей функции `create_merged_pdf()`. Это включает конвертацию `.docx` в `.pdf` при необходимости и извлечение его оглавления (TOC).

*   **Шаг 2: Выбор папки с приложениями.**
    *   С помощью `filedialog.askdirectory()` пользователю будет предложено выбрать папку.
    *   Если папка не выбрана, операция прерывается.

*   **Шаг 3: Обработка приложений из папки.**
    *   Программа получит список всех файлов с расширением `.pdf` из выбранной папки.
    *   Список будет отсортирован **по алфавиту** для обеспечения предсказуемого порядка.
    *   Будет запущен цикл по отсортированному списку файлов. Для каждого файла (`i`-го по счету):
        1.  **Текст для штампа:** Текстом для штампа в правом верхнем углу будет **имя файла без расширения**.
        2.  **Создание временного PDF:** Будет создана временная копия PDF-приложения, на каждую страницу которой нанесен указанный штамп.
        3.  **Извлечение оглавления (TOC):** Из *оригинального* файла приложения будет извлечено его собственное оглавление.
        4.  **Сбор данных для закладки:** Информация (порядковый номер `i+1`, извлеченное оглавление, имя файла) будет добавлена в список `attachments_data`.

*   **Шаг 4: Финальная сборка.**
    *   Все временные PDF (основной отчет + обработанные приложения) будут объединены в один итоговый PDF-файл.
    *   Пользователю будет предложено выбрать имя и место для сохранения этого файла.
    *   С помощью функции `compose_multi_attachment_toc` будет создано оглавление. Закладка для каждого приложения будет иметь формат **`Prilog {i+1} - {имя файла}`**.
    *   Созданное оглавление будет применено к итоговому PDF.

*   **Шаг 5: Очистка.**
    *   Все временные файлы, созданные в процессе, будут удалены.

**4. Затрагиваемые модули**

*   `pdf_attachments_ui.py`: Основные изменения, добавление UI и новой функции.
*   `pdf_attachments/bookmarks.py`: **Без изменений.** Будет переиспользована существующая функция `compose_multi_attachment_toc`.
